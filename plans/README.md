## Findings considered and rejected

- **Rewrite MCP subprocess cleanup:** not recommended in this quick pass. The current code terminates process groups and joins the reader thread in `nextorca/mcp_stdio.py`; `tests/test_mcp_stdio.py` already includes a timeout/process-termination regression test. No concrete additional defect was verified.
- **Add Vercel deployment configuration:** not applicable. NextOrca is a Python CLI package without a web deployment target.
- **Move every test to comprehensive CI:** rejected. Fast PR checks should still run all tests that do not require the Linux Bubblewrap runtime.

## Vetted comparison findings

| Finding | Category | Impact | Evidence | Confidence |
|---|---|---|---|---|
| The current interactive UX is a line-oriented `input()` REPL; there is no full-screen TUI | Direction / DX | Makes conversation navigation, live status and approvals less discoverable | `nextorca/repl.py`; `nextorca/cli.py`; `docs/ROADMAP.md` backlog item 1 | HIGH |
| SQLite sessions are persisted but there is no workspace-scoped list/search/resume picker | DX | Users must retain and supply `--session-id` manually | `nextorca/session_store.py` has create/get/load APIs but no listing/search; `nextorca/cli.py` only exposes `--session-id` and `--session-stats` | HIGH |
| Provider protocol exists but CLI wires only OpenAI-compatible adapters | Direction / DX | Additional protocols require explicit construction/configuration and adapter contract tests | `nextorca/provider.py`; `nextorca/openai_compatible.py`; `nextorca/cli.py` provider construction | HIGH |
| Context compaction is session-local; no cross-session project memory store or retrieval was found | Direction / perf | Decisions and project facts do not automatically carry across separate sessions | `nextorca/context.py`; `nextorca/session_store.py`; `docs/ROADMAP.md` | HIGH |
| Atomic's browser, remote channels, managed inference, desktop sidecar, schedules and broad tool catalogue are absent from NextOrca | Direction | Feature-count parity would greatly expand product scope, dependencies and safety boundaries | Atomic `src/tools/browser/README.md`, `src/local-llm/README.md`, `src/tasks/README.md`, `src/channels/README.md`, `src/tui/README.md`; NextOrca `docs/ROADMAP.md` | HIGH |

## Findings deliberately not turned into immediate implementation plans

- Browser automation / attach to personal Chrome: defer until a concrete browser task justifies its credential, page-content and action-approval surface.
- Desktop app, sidecar, HTTP remote access and Telegram/Discord: defer because the product is explicitly terminal-first and these introduce new control/identity boundaries.
- Scheduled/overnight autonomy: defer; interactive goal mode and verification currently fit the project scope.
- Managed local model lifecycle: defer; external OpenAI-compatible local endpoints keep the runtime small and model backend-agnostic.
- Plugin marketplace and broad plugin ecosystem compatibility: defer; standard Agent Skills, local declarative plugins and MCP already cover local extensibility.
- Parallel subagents: defer until process cancellation, resource limits, approval ownership and real-repository evaluation are stronger.
- Document parsing/media generation/desktop control: do not add for parity alone. Add a dedicated tool only when repeated personal coding workflows require it.
- GAIA score parity: rejected as a proxy for coding-agent quality; prioritise verified changes on reproducible real project tasks.
